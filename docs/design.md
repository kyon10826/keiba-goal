# keiba-goal 設計書 (v1)

普通の JRA 開催日に使う「券種別の確率予測 + 目標到達型 (Goal-reaching) の買い目推奨」システム。
2026 年のコンペ用コード (keiba_mlops) とは独立した新リポジトリとして 1 から作る。

- 作成: 2026-10-29
- 状態: ドラフト (レビュー前)

---

## 0. 目的・やらないこと

**目的**
1. 単勝・複勝それぞれの的中確率を、校正された確率として出す (券種別モデル)。
2. 1 日の予算 x・目標額 A・その日に買う回数 k を朝に決め、各レースの発走 5 分前に「目標に届く確率を最大にする」単勝・複勝の買い目と金額を推奨する。
3. その日の結果 (払戻) で資金を更新し、目標到達 / 回数切れ / 資金切れで終了する。

**やらないこと**
- 馬券の自動購入 (推奨の表示と記録まで)。
- JRDB など有料データ (手元データ + netkeiba の公開ページのみ)。
- 馬連・三連系 (v1 は単勝・複勝のみ。PDF の最終運用も単勝・複勝候補だった)。
- 障害レース (平地のみ学習・推奨。全レースの 3.7%)。

**前提として明記すること (成果報告でも毎回書く)**
- 参照した 2 資料とも、モデル単体で市場 (オッズ) に勝てた証拠はないと結論している。
- Goal-reaching は期待値がマイナスのまま「目標に届く確率」を最大化する方策。平均すると資金は減り、多くの日は予算の大半を失う。

## 2. 実行環境

- Python 3.12 (uv の venv、リポジトリ直下 `.venv`)。CLT の Python 3.9 は使わない (EOL、FLAML 最新版が入らない)。
- 主な依存: polars, pyarrow, numpy, pandas (sklearn/FLAML 連携用), scikit-learn, lightgbm, xgboost (<3, FLAML の互換範囲), catboost, flaml[automl], optuna, requests, beautifulsoup4, lxml, pyyaml, matplotlib, shap (評価のみ), pytest。
- マシン: Apple M2 / 8 コア / **メモリ 8GB** / 空きディスク約 52GB。
  - 特徴量は polars で年単位に作り parquet (zstd) に保存。学習時は必要列だけ float32 で読む。
  - 1.1M 行 × 400 列 × float32 ≈ 1.8GB。学習器ごとのビン化コピーを考えると、全期間 × 全学習器の同時保持はしない。
  - CatBoost は `allow_writing_files=False`、作業ディレクトリを汚さない。
  - macOS の multiprocessing は spawn。並列処理は必ず `if __name__ == "__main__":` ガードの内側で。
- 外部パス (config で指定、コピーしない):
  - 成績: `/path/to/src/data/data/record_data_*.csv`
  - 時系列オッズ: `/path/to/src/data/Time_Series_Odds/{JD,JR,JW}*.CSV`
  - 公式列仕様: `/path/to/2026/データ仕様書_AI競馬予想マスターズ学生_2026.xlsx`
- 生成物はすべて `data/` (gitignore) 配下: `data/raw/netkeiba/` (HTML キャッシュ, gzip)、`data/interim/` (正規化済み parquet)、`data/features/`、`data/models/`、`data/sessions/`、`data/backtest/`。

## 3. データ

### 3.1 成績データ (record_data, 47 列)

- 44 ファイル (1986〜2024 年次 + 2025 のスナップショット 5 本)。Shift-JIS、ヘッダ無し、全行 47 列。値の前後空白は strip。
- 2025 は**最新スナップショット 1 本だけ**読む (古いスナップショットは最新の部分集合。全部読むと最大 5 重複)。現状 `record_data_2025_20250919.csv` (2025-01-05〜09-15)。
- 列名・意味は公式仕様 (xlsx の「成績データ」シート) に従う。dtype は明示する (推論させない)。
- キー:
  - `race_id` 18 桁 = YYYYMMDD + 場(2) + 回(2) + 日(2, A/B/C=10/11/12) + R(2) + 馬番(2)。
  - `race_key = race_id // 100` (16 桁) = 時系列オッズのレース ID。
  - `nk_race_id` (netkeiba 12 桁) = YYYY + 場 + 回 + 日 + R。
  - `date` は race_id 先頭 8 桁から作る (year 列は 2 桁なので使わない)。
- 異常区分 `error_code` (JV 異常区分): 0 正常 / 1 出走取消 / 2 発走除外 (1999 年まで) / 3 競走除外 / 4 競走中止 / 5 失格 / 6 落馬再騎乗 / 7 降着。
- `horse_N` は取消馬を含む登録頭数。**出走頭数 `starters` = レース行数 − (error_code ∈ {1,2,3} の行数)** を別に持つ。
- 発走前に使える列 (27) と、レース後にしか分からない列 (rank, time, time_diff, corner1-4, last_3F_time/rank, Ave_3F, PCI, -3F差, leg, prize, error_code, **確定 win_odds, 確定 pop**) を区別する。後者は「過去走」としてのみ使う (同じレースの値は特徴量に使わない)。
- `leg` (TARGET 式の脚質) は再現できない (netkeiba から作れない) ので使わない。代わりに通過順位から自前の先行度を全行で同じ式で作る。
- `class_code` は非公式の TARGET 式コード。序数マップを固定で持つ (7 未勝利, 15 新馬, 11 未出走, 19 400万下, 23 500万下/1勝, 39 900万下, 43 1000万下/2勝, 63 1500万下, 67 1600万下/3勝, 115 L, 131 OP, 147 重賞(格付けなし), 163 G3, 179 G2, 195 G1、アラブ系 27/31/35 と 59 は平地サラ系の学習から除外)。序数: 新馬/未出走/未勝利=0, 400-500万/1勝=1, 900-1000万/2勝=2, 1500-1600万/3勝=3, OP/L=4, 重賞/G3=5, G2=6, G1=7。
- `track_code` (JV): 10-22 芝 (直線/左/右/内外)、23-29 ダート、51-59 障害。芝ダ・回り・内外に分解する。

### 3.2 時系列オッズ (JD / JR / JW)

- JD = 単勝 + 複勝 Lo/Hi、JR = 馬連 153 組、JW = 枠連。期間 2003-10-04〜2024-12-28。**2025 年以降は無い**。
- ファイル名: 種別(2) + 場(2) + 年(2) + 回(1) + 日(1, 16 進: A-C=10-12) + R(2)。中の 16 桁 ID = record_data の race_key。
- 列 (JD): レースID, 区分, 月日時分(MMDDHHMM, 年なし), 頭数, 単勝票数, 複勝票数, 以降 馬ごとに (単勝, 複勝Lo, 複勝Hi)。0.0 は「未発売/取消/票なし」→ NaN。
- 区分: 1 中間 / 2 前日売最終 / 3 最終 (締切) / 4 確定。**区分 3・4 は確定オッズ = 特徴量に使わない**。2022 年以降は最後の区分 1 行が締切後のことがあるので「最後の行」は使わない。
- 基準時刻 `ref` = 区分 3 の時刻 (≒ 発走時刻 + 0〜2 分)。T-x スナップショット = 区分 ∈ {1,2} のうち時刻 ≤ ref − x 分の最後の行。鮮度上限: T-120/60 は 10 分、T-30 は 5 分、T-5 は 3 分 (超えたら NaN + 欠損フラグ)。
- 出力 (年ごとの parquet): `ts_win_{year}.parquet` (race_key, horse_num, x ∈ {120,60,30,5}, win, place_lo, place_hi, staleness_min) と `ts_final_{year}.parquet` (確定単勝・複勝 Lo/Hi; 評価とオッズ下落率の推定にだけ使う)。JR は v1 では使わない (馬連は v2)。
- 抽出は 8 プロセス並列で 1 種別 1 年 3 秒程度 (棚卸しで検証済みのレシピあり)。
- **オッズ下落率表 q0.1**: 確定 / T-5 の比の 10 パーセンタイルを (券種 {単勝, 複勝Lo} × T-5 オッズ帯 [1,3) [3,5) [5,10) [10,20) [20,50) [50,100)) で、2019-2024 から推定して保存 (年代で悪化しているため直近を使う)。参考: 単勝 0.79-0.94、複勝Lo 0.82-0.92。

- **補完クロール (再開可能、キャッシュ済みは再取得しない)**:
  1. 2025-09-16〜現在の結果 (推定 3,900 レース、約 3 時間): 直近の馬の履歴に必須。
  2. 2023-2024 の結果ページ (6,910 レース、約 5 時間): 複勝の実払戻 (バックテストに必須) と調教師。

- 補完行は `source="netkeiba"` を付けて record 行と同じスキーマの `history.parquet` に統合。重複 (race_id) は record 側を優先。
- 開催日の自動判定: 日付ごとに race_list_sub を 1 回取り、レースが無ければスキップ。

### 3.4 払戻データ (バックテスト用)

- `payouts.parquet`: race_key, bet_type ∈ {win, place}, horse_num, payout_per_100。結果ページの払戻表から。
- 単勝は「確定オッズ × 100」で再現できる (同着の年 0-9 レースを除く)。同着・特払いは払戻表の値を使う。
- 複勝は払戻表が唯一の情報源。払戻が取れていないレースはバックテストから除外し、除外数を報告する (推定値で埋めない)。

## 4. 特徴量 (約 380 列)

### 4.1 原則

- **すべて「そのレースの発走前に分かること」だけで作る**。
  - 馬の過去走: 同じ馬の前走以前 (`shift(1)` 相当、同日のレースは含めない)。
  - 騎手・種牡馬などの集計: **前日まで**の累積 (as-of、expanding)。学習期間全体で集計した値を同じ行に戻す (in-sample target encoding) は禁止 (旧実装はこれで騎手勝率の AUC が学習内 0.78 / 学習外 0.54 になっていた)。
  - オッズ: T-120/60/30/5 のスナップショットのみ。確定オッズ・確定人気・区分 3/4 は禁止。
  - 当日馬体重は発走約 50 分前に公表 → T-5 の判断時点では使える。T-120 時点の予測は行わない (判断は T-5 のみ)。
- 実装は polars (遅延評価)。並び順は (date, race_key, horse_num) を明示 (CSV は場順で、時系列順ではない)。
- カテゴリのエンコードは学習期間で固定した語彙 (`data/models/vocab.json`)、未知は専用の値。推論時に作り直さない。
- 欠損は NaN のまま (GBDT が扱う)。0 埋め禁止。オッズは欠損フラグ付き。
- 各特徴量はレジストリに (名前, グループ, 元列, 発走前に分かるか, 作る関数) を登録。テストで「元列にレース後情報が無い」ことを検査する。

### 4.3 ライブとの一致 (train/serve parity)

- 学習用の特徴量生成とライブ推論は**同じ関数**を使う。ライブでは「当日の出走馬の過去走 (history.parquet) + 前日までの集計表 + 当日の出馬表・オッズ」を入力に、当日行だけを出力する。
- パリティテスト: 2024 年のある開催日を「ライブ方式」(その日より前だけの履歴) で作り、学習用特徴量ストアの同じ行と一致することを検査 (オッズ列は同じスナップショットを与える)。

## 5. 目的変数とクレンジング

- 学習・評価対象: 平地、出走した馬 (error_code ∉ {1,2,3})、出走頭数 ≥ 5。
- **単勝**: 確定着順 1 (同着は両方 1)。
- **複勝**: 出走頭数 ≥ 8 なら 3 着以内、5〜7 なら 2 着以内 (≤ 4 は複勝発売なしで対象外)。同着は払戻規則どおり両方正例。
- **ノイズ除去 (学習のみ)**: error_code ∈ {4,5,6} (中止・失格・落馬再騎乗) を含むレースを丸ごと学習から除く (約 5.8%。SpeakerDeck の「4〜5%」に相当)。評価 (検証・テスト) では除かない (本番では事前に分からないため)。

## 7. 学習 (SpeakerDeck の改良モデル方式を券種ごとに)

単勝・複勝それぞれについて:

1. **学習器の選択 (FLAML)**: estimator_list = [lgbm, xgboost, catboost], metric = log_loss, 開催日境界の時系列 CV (4 分割)。メモリ 8GB のため探索は学習期間の直近 7 年 (2014-2020, 約 33 万行) で行う。time_budget は設定値 (既定 2 時間)。
2. **ハイパーパラメータ調整 (Optuna)**: 選ばれた学習器について、同じ時系列 CV・log_loss で TPE 探索 (既定 30 試行、seed 固定)。探索空間は学習器ごとに定義。
3. **最終学習**: 最良設定で学習期間全体 (2004-2020) を学習、2021 で早期終了。seed を変えて 5 本 → 予測を平均。
   - `scale_pos_weight` などのクラス重みは使わない (確率の校正が壊れ、旧実装で木 1 本に縮退した)。
4. **校正**: 2022 年 (学習に使っていない年) の予測で Isotonic 回帰。
5. **レース内正規化**: 単勝はレース内で合計 1、複勝は合計 = 支払い着数 (3 または 2、1 を超える値は切って再配分)。
6. 保存物: `data/models/{win,place}/` に各 seed のモデル、校正器、特徴量リスト、語彙、学習設定、FLAML/Optuna の探索ログ、評価レポート。

AutoML と Optuna の両方を使うのは資料どおり (FLAML で学習器と大まかな設定、Optuna で詰める)。計算量の制御: 探索はサブ期間、最終学習のみ全期間、学習器ごとにデータを作り直さず 1 つずつ解放する。

## 9. 投票: Goal-reaching (PDF 方式)

### 9.1 1 日のセッション

- 朝に予算 x0、目標 A (> x0)、その日に買う最大回数 k0 を決める。
- 各レース (発走時刻順) の T-5 で判断。買ったら k を 1 減らす。見送りは k を減らさない。
- 実効の残り回数 `k_eff = min(k, その日の残りの対象レース数)`。
- 終了条件: 資金 ≥ A (目標到達)、k = 0、資金 < 100 円、当日のレース終了。

### 9.2 理論 (PDF 9 枚目)

現在資金 x、目標 A、残り回数 k、控除率 c (単勝・複勝 0.20):

- 不足率 r = (A − x) / A
- 狙う有効オッズ o*_k = 1 / (1 − r^(1/k))
- 1 回の的中確率 (公正オッズ相当) p* = (1 − c) / o*_k
- 期限内の到達確率 P*_k = 1 − (1 − p*)^k
- Bold stake: 的中時にちょうど A に届く賭け金 s = (A − x) / (o − 1)

性質: o*_k は外れても変わらない (外れ後の r' = r^((k−1)/k) で再計算すると同じ値)。k 回全部外れると資金 0。
理論上限チェック: 控除率がある限り資金は優マルチンゲールなので **P(到達) ≤ x / A**。計算上の到達確率がこれを超えたら計算の誤りとして停止する。

### 9.3 買い目の決定 (PDF 10 枚目)

1. 候補: 各馬の単勝・複勝 (計 2 × 出走頭数)。確率は校正・正規化済みの p̂。
2. オッズは T-5 スナップショット o (複勝は Lo)。下落補正 ō = o × q0.1(券種, オッズ帯)。
3. 除外: o ≥ 100 倍、オッズ欠損、取消馬。同じ馬の単勝と複勝は片方だけ。
4. バスケット B の有効オッズ o_eff = (Σ_{i∈B} 1/ō_i)^−1 を o*_k に近づける (o_eff ≥ o*_k × 0.9 を許容範囲)。
5. その中で「重なりを補正した的中確率 P(B のどれかが当たる)」を最大化する。
   - 単勝同士は排反なので和。複勝は他の券と重なるため、Plackett–Luce の着順シミュレーション (強さは単勝・複勝の校正確率の両方に周辺確率が合うよう反復調整) で P(どれかが当たる) を求める。
   - 探索: 候補を EV = p̂·ō の降順に並べ、Σ1/ō が 1/o*_k に届くまで加える貪欲解と、候補上位 12 からの全探索 (小さい組合せ) の良い方。
6. 金額: 総額 S = (A − x) / (o_eff − 1) (ただし S ≤ x)。各券 s_i = S × o_eff / ō_i (どれが当たっても払戻が同じになる配分)。100 円単位に丸め、丸め後に o_eff・到達額・EV を再計算。
7. ゲート: EV = Σ p̂_i ō_i s_i / Σ s_i ≥ τ (0.8) のときだけ購入推奨。満たさなければ見送り。強制購入はしない。
8. 出力: 買い目 (券種・馬番・金額)、o*_k、o_eff、P(的中)、EV、P*_k、当たった場合の資金、理論上限 x/A。

### 9.4 モジュール

- `betting/theory.py` (式) / `betting/basket.py` (候補・探索・配分) / `betting/simulate.py` (PL シミュレーション) / `betting/session.py` (1 日の状態、JSON 永続化、監査ログ)。純粋関数として実装し、ネットワーク・ファイル I/O から分離してテストする。

## 10. バックテスト

- 期間: 2023-2024 (T-x オッズがあり、モデルが学習していない期間)。開催日ごとに 1 セッション (x0, A, k0 は引数。既定 1 万円 → 3 万円、k0 = 6)。

## 14. 主なリスク

- **計算資源**: FLAML × 3 学習器 × CV × Optuna × 5 seed は M2/8GB で数時間〜十数時間。時間予算・サブ期間探索・段階ごとの保存と再開で抑える。
- **市場に勝てない**: オッズを特徴量に入れたモデルは市場とほぼ同じ意見になる。評価で市場比較を必ず出し、過大な期待をさせない。
- **2025 年以降のオッズ時系列が無い**: オッズ特徴量込みのモデルは 2025 年で正式評価できない。ライブ運用分は自前の収集ログで後から評価する。
- **netkeiba**: 規約・負荷・レイアウト変更。間隔 2.5 秒以上、キャッシュ、fixture テスト、取得件数の検査 (例: 出走頭数ぶん体重が取れたか) で壊れたら止める。
- **払戻の欠落**: 複勝の実払戻はクロールでしか得られない。取れなかったレースは推定で埋めず除外して報告。
